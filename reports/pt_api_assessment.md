## 1. Executive Summary

- **Different lineages, sharply different scopes:**
  - **`zamaudio/ptformat`** (`1,337` LoC `ptformat.cc`) is the original 2015–2019+ C++ reader built to import **legacy through early modern sessions (PT `5`–`12`, `.pts`/`.pt5`/`.ptf`/`.ptx`, both Big-Endian PPC and Little-Endian x86)** into Ardour. It extracts only **audio file names/lengths, audio regions (flattening multi-channel tracks), basic audio timeline placements, and MIDI note regions (`MdNLB`)**, with a dummy missing-audio shell-script emitter (`ptgenmissing`) and target-rate sample rescaling (`_ratefactor`).
  - **`sebedard-creator/pt_api`** (`10,805` LoC monolithic Python stdlib library, `v1.6.3`) is a **template-bound surgical editor & importer/relinker** for Little-Endian `.ptx` sessions (`v10`–`v12`/`2026`), adding BWF/UMID audio import, marker deletion, clip trim/move/fade/clip-group mutations, track visibility, and sample-based main volume/pan automation, while dropping MIDI, plug-ins, sends, aux/master/folder routing, tick-mode automation, and clean-room session creation.
  - **`ptx-session-kit` + `scraft-bridge`** (`34,334` LoC clean-room Python + Rust) is a **full clean-room from-scratch binary reader, writer, verifier, and ecosystem bridge**: it builds `.ptx` sessions from scratch without donor templates (`newbase`/`newsong`/`PtxBuildSpec`), rebuilds `0x0002` byte-identically, handles Audio, MIDI, Instrument, Aux, Master, Folders, VCA read, `17` stock AAX plug-ins + `0x260F` curves, `10` pre/post sends, `LFE`, `MPE`, tick & sample automation, centered (`34 B`) & post (`32 B`) crossfades, multi-width Sync Points (`b2 & 0x0F`), Clip Groups (`0x262C`/`0x2428`), `19/19` SMPTE timecode rates, live `PTSL`/`ESI`/`BounceTrack` verification, plus bidirectional SoundCraft `.scraft`/`.scraftz` export (`ptxconv`).
- **Three-Way Reliability Reality Check (Empirically Measured Across `12` Real Sessions):**
  - `ptx_decode_v01-27.py` decoded **`10/10` `.ptx` files cleanly (`0` warnings)** and descrambled `xt=1` `.ptf` files, while failing to decode Big-Endian PT 5 `.pts` (`be=1`) headers and legacy PT 5–9 block tags (`0x1008`/`0x1011`/`0x2001`), and omitting `.mxf` in `AUDIO_EXT`/`AUDIO_EXTS` (`TestMXF.ptx`).
  - `pt_api v1.6.3` succeeded cleanly on only **`2/12`** sessions (`TestMXF.ptx` with `physical_filename=None`, `T02A_v05_crossfade-200ms.ptx`) and threw `ValueError` exceptions on **`10/12`** (including both Sync Point fixtures `0x32`/`0x33`, `CR_max_intro`, `sc_v0.20.1`, `Stratosphere`, `MIDI_T24`, `RegionTest`, `TestPTX`, `goodplaylists2.ptf`, `Damien_monos.pts`).
  - `zamaudio/ptformat` passed all `8` of its own regression bins (including PT5 BE `.pts`, PT8 `.ptf`, and PT `2026.4.0` `TestMXF.ptx`), rejected clean-room `CR_max_intro_v01-00.ptx` and `sc_v0.20.1.ptx` (`EXIT 255: Cannot extract version`), and **silently corrupted** `B1_s1_ptsl.ptx`, `B1_ticks.ptx`, and `Stratosphere` sample positions/lengths due to 32-bit `0x104F` truncation on `10^12` ticks and missing `b2 & 0x0F` sync-point width parsing.

## 4. Proven Bugs, Fragilities & Assumptions in `ptformat` and `pt_api` (Do NOT Copy)

| Package | Defect / Assumption Verified in Source or Tests | Observed Impact |
|---|---|---|
| **`ptformat`** | **Hardcoded `0x1f` version gate (`ptformat.cc:475`)** (`parse_block_at(0x1f, ...)` + raw byte offsets `0x40`/`0x3d`/`0x3a` + `_version > 12` reject) | Rejects clean-room sessions (`CR_max_intro_v01-00.ptx`, `sc_v0.20.1.ptx`) with `EXIT 255: Cannot extract version` when `0x0003`/`0x2067` is not preceded by an 11-byte header block (`0x14 + 11 = 0x1f`). |
| **`ptformat`** | **32-bit `u_endian_read4` truncation on `0x104F` (`ptformat.cc:1041`)** + ignoring `o[14] == 0x40` tick flag | Truncates 5-byte `u40` offsets (`OFF12 = 10^12 + ticks`), outputting bogus sample positions (`3,567,987,200` on `B1_ticks`, `3,636,707,328` on `Stratosphere`) and overflowing at `>= 24.8h` (`2^32` samples). |
| **`ptformat`** | **Missing `b2 & 0x0F` sync-point width nibble (`ptformat.cc:772`)** | Reads `sync_offset` bytes as `length` on `B1_s1_ptsl` and `B1_ticks` (`13,641,488` samples instead of `48,000`). |
| **`ptformat`** | **Unfiltered byte-by-byte recursive `0x5A` scanner (`ptformat.cc:552`)** (`FLAT_CTS` / `RAW_PREFIX` absent, `MAX_CONTENT_TYPE = 0x3000` unused) | Can recurse into opaque binary payloads (`0x0002`, `0x1054` `count=90 = 0x5A`), misparsing child blocks. |
| **`ptformat`** | **Hardcoded `0x103A +11` offset + substring folder skips + blind `0x1001` increment (`ptformat.cc:685-761`)** | Skipping `"Audio Files"` / `"Fade Files"` via `foundin()` breaks if a project/user path contains those substrings and can desynchronize linear `wav++` length assignment from `0x1003 > 0x1001`. |
| **`ptformat`** | **Unchecked iterator dereferences (`ptformat.cc:897, 1194`)** (`*c->child.begin()`, `*(midichunks.begin()+rindex)`) | Undefined behavior / crash on malformed or empty `0x2629` / out-of-range MIDI `rindex`. |
| **`ptformat`** | **Channel flattening & omitted domains** | Splits stereo tracks into separate `track_t` entries; drops all fades, clip gain, clip loops, compound groups (`0x2523` `FIXME`), markers, tempo/meter/key, SMPTE rates, mixer/pan/sends, plug-ins, and automation. |
| **`pt_api v1.6.3`** | **Narrow `0x2628` width whitelist (`0x22` only), `0x204D +40`, fade-size rejection, mandatory `0x1054`, `0x5100` ClipGroup failure** | Crashes with `ValueError` on **`10/12`** benchmarked sessions (`0x32`, `0x33`, `23 B` fade-in, MIDI-only sessions without `0x1054`, `Stratosphere` `0x5100`, `RegionTest`, `TestPTX`, `.ptf`/`.pts`), leaves `TestMXF` `physical_filename=None`, and drops PT 2026 `tag=2` markers & MIDI/FX/tick lanes. |
